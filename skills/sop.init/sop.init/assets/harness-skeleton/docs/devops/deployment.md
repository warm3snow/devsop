## 2. 制品

- 构建产物：{{Docker 镜像 / 二进制}}
- 制品仓库：`{{Harbor / 制品库地址}}`
- 命名规则：`{{repo}}:{{branch}}-{{git-sha7}}-{{timestamp}}`
- 必须注入：`build_time`、`git_commit`、`version`（通过 `make build` 自动处理）
- 保留策略：
  - 生产：≥**1 年**
  - 预发：≥**90 天**
  - 测试：≥**30 天**

## 3. 配置管理

### 配置中心
- 工具：{{Apollo / Nacos / etcd / 自研}}
- 配置文件：`etc/*.yaml`，分环境维护（`etc-dev.yaml` / `etc-test.yaml` / `etc-prod.yaml`）

### 敏感配置
- **【禁止】** 把真实凭证、密钥、Token 提交到代码库
- **【必须】** 通过环境变量或 KMS/Vault 注入：
  ```yaml
  jwt_secret: ${JWT_SECRET}
  mysql_dsn: ${MYSQL_DSN}
  ```
- **【必须】** JWT/会话密钥强度：≥**32 字符**，使用 CSPRNG 生成
- **【必须】** Redis 密码不明文写在 yaml；使用环境变量注入
- 配置变更必须走流程：审核 → 灰度 → 全量 → 留存变更记录

### 环境隔离
- 不同环境使用**不同的**密钥、Token、第三方账号
- **禁止**测试环境连生产 DB / 第三方真实账号

## 4. 发布流程

```
1. 预检：CI 全绿 + Code Review 通过 + 关联单号
2. 测试环境：自动部署（CI 触发）
3. 预发环境：人工审批 + 冒烟用例
4. 生产环境（金丝雀阶梯）：
   5% → 等待 {{15 分钟}} → 25% → 等待 {{30 分钟}} → 50% → 等待 {{30 分钟}} → 100%
   每阶梯监控核心指标，告警则自动暂停
5. 回滚：触发条件 + 命令 + 数据兼容性确认
```

### 灰度阶梯阈值
- 错误率 > **1%** 暂停
- P99 延迟 > {{1s}} 暂停
- 业务核心指标偏离基线 > **5%** 暂停

### 回滚
- **必须**保留上一稳定版本制品至少 30 天
- 回滚命令必须演练（至少季度一次）
- 数据库迁移**禁止**直接物理回滚（用 forward fix）

## 5. 健康检查

| 探针 | 端点 | 通过条件 | 间隔 |
|------|------|----------|------|
| Liveness | `GET /healthz` | HTTP 200 | 10s |
| Readiness | `GET /ready` | 200 + 依赖（DB/Redis/必备下游）就绪 | 10s |
| Startup | `GET /startup` | 启动完成 | 启动期 5s |

- 启动时间预算：≤**60s**
- 健康检查**禁止**调用第三方耗时接口

## 6. 监控告警

### 指标平台
- 指标：{{Prometheus + Grafana}}
- 日志：{{ELK / Loki / CLS}}
- 链路追踪：{{Jaeger / SkyWalking}}
- APM：{{Sentry / Datadog}}

### 必备指标
- 错误率（HTTP 5xx / 业务错误码）
- P50 / P95 / P99 接口延迟
- QPS / 调用量
- 依赖可用性（DB、Redis、下游服务）
- 资源占用（CPU、内存、磁盘、连接数）
- 业务核心指标：{{订单量、支付成功率、登录成功率…}}

### 告警阈值（默认值，按业务调整）

| 指标 | 警告 | 严重 |
|------|------|------|
| 错误率 | > 0.5% 持续 5min | > 1% 持续 1min |
| P99 延迟 | > 800ms 持续 5min | > 1s 持续 1min |
| CPU 使用率 | > 70% 持续 10min | > 85% 持续 5min |
| 内存使用率 | > 75% 持续 10min | > 85% 持续 5min |
| 磁盘使用率 | > 80% | > 90% |
| 连接池饱和度 | > 70% | > 85% |
| 慢查询数 | > 10/min | > 50/min |

### 告警通道
- {{企业微信群 / 短信 / 电话}}
- 严重告警必须电话；重复 3 次未响应升级到 leader

## 7. 容量规划

- 单实例容量基线：{{QPS 上限 + 资源配置}}
- 弹性策略：{{HPA / 手动扩缩容}}
- 大促/活动：必须**提前压测**（至少 N+1 倍流量），扩容到位再上线

## 8. 日志规范

- 生产日志级别：**info**（debug 仅限故障排查临时开启）
- **【禁止】** 日志输出：密码、Token、密钥、完整身份证、银行卡、指针值
- **【必须】** 关键路径日志：请求入口（含 trace_id）、外部调用（成功/失败）、错误堆栈
- 日志格式：JSON 结构化，便于检索
- 日志留存：≥**30 天**（合规场景按要求延长）
- 日志体积：单实例日均 ≤{{10GB}}（超出考虑采样或下沉）

## 9. 应急预案

| 故障类型 | 现象 | 应对动作 |
|----------|------|----------|
| 依赖 X 不可用 | 告警 + 错误率上升 | 开关降级 + 联系上游 + 切备 |
| 流量突增 | CPU/QPS 飙高 | 限流 + 扩容 + 排查异常调用方 |
| 单机异常 | 单机告警 | 流量摘除 + 重启 + 复盘 |
| DB 慢/锁表 | 慢查询暴增 | kill 慢查询 + 切只读 / 主备切换 |
| 缓存雪崩 | DB 压力骤增 | 限流 + 缓存重建 + 热点 key 复查 |

每个预案必须**演练**（季度一次），并记录到 [failures.md](failures.md)。

### 启动方式

#### 方式一：拉起模拟服务（完整联调）

- **统一编排**：使用 `{{docker-compose / Makefile / 脚本}}` 一键拉起所有模拟服务

> **原则**：服务必须能在上下游缺失时正常启动。核心依赖走 Mock，非核心依赖走降级。

### Mock 数据管理

- 目录：`{{mocks/}}`，按服务名分子目录
- 数据格式：{{JSON / YAML / Proto}}
- **【推荐】** Mock 数据纳入版本管理，团队共享

### 调用约定

| # | 规范 | 说明 |
|---|------|------|
| 1 | **【必须】** 通过配置切换真实/模拟地址 | 禁止硬编码模拟地址到业务代码 |
| 2 | **【必须】** Mock 服务地址使用环境变量 | 如 `{{SERVICE_NAME}}_ADDR=localhost:{{port}}` |
| 3 | **【必须】** Mock 数据覆盖正常 + 异常场景 | 至少包含：成功、参数错误、超时、服务不可用 |
| 4 | **【禁止】** Mock 服务暴露到公网 | 仅限本地/内网使用 |
| 5 | **【禁止】** 生产配置指向 Mock 服务 | CI 中增加检查，防止误配 |

## 11. 禁止项

- ❌ 直接登录生产服务器手动改文件 / 跑脚本
- ❌ 跨过审批流程直接发布
- ❌ 在生产执行未演练的 SQL（DDL / DML）
- ❌ 测试环境用真实生产数据（必须脱敏）
- ❌ 关闭生产监控 / 告警（除维护窗口）
- ❌ 上线时间窗口外发布生产（除非紧急 hotfix，且事后补流程）
