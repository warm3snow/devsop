## 6. Test Tools and Environment

> Dependencies in integration testing (DB / cache / MQ) are provided by real services started via **testcontainers or docker-compose**, or by test endpoints injected by CI; instance management / data preparation use the project's actual IT tools or fixtures.

| Operation | Approach (Go / go-zero) |
|------|---------|
| Start dependency services | `docker compose -f docker-compose.it.yml up -d` or testcontainers-go started/stopped in `TestMain` |
| Database query / cleanup | Connect directly to the test DB and run SQL, or use project-provided scripts like `make it-db-reset` |
| Call interfaces | Send requests directly to the test environment endpoint (`httptest` / `resty` / `grpc` client), no intermediate proxy needed |
| Clean up resources | Each case has its own `defer` teardown or a global `TestMain` teardown hook |

## Decision Framework

1. **Real traffic first**: prefer real (desensitized) traffic over constructed data when available.
2. **Fault injection**: proactively trigger timeouts, 404, 500, network jitter, and observe whether the system behaves as expected.
3. **Data isolation**: data generated by IT must either have an independent tag for cleanup or be listed in a post-test cleanup step.
4. **No loose ends**: every ❌ case must have root cause + fix + retest; "fix later" is not acceptable.
5. **Logs as evidence**: every case must paste the key original log excerpt (1-3 core lines) to prove IT actually ran and the results are valid. Writing only ✅/❌ is invalid IT and will be rejected in re-review.

---

## Anti-examples

❌ **Anti-example 1: failing cases "fix next time"**
> 3 of 10 cases failed, written as "known issue, does not block merge".

✅ **Principle**
> Either fix them, or explicitly downgrade to a known limitation and register it in Docs; you cannot gloss over it.

❌ **Anti-example 2: no req_id recorded**
> Only wrote ✅ / ❌ after running the case; later issues cannot be traced.

✅ **Principle**
> Each case must record at least one req_id / trace_id for later oncall / tracing.

❌ **Anti-example 3: no log excerpt pasted**
> The case wrote ✅, but the "key log excerpt" column is empty or only says "normal" / "as expected".

✅ **Principle**
> Each case must paste 1-3 core log lines proving the case passed. No logs = IT not done = rejected and retested.
