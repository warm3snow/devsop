# glossary.md 特殊子 Agent 指令

> 本文件作为 `glossary.md` 子 Agent 在通用 prompt 基础上的**补充指令**。主 Agent 调度 glossary.md 子 Agent 时，将本文件内容一并传入。

---

## 核心原则：宁缺毋滥

**只记录本项目私有的、非公知的术语。** 15 条精准的私有术语 > 60 条混杂公知的废话表。

## 收录标准（三连问，全部"是"才收录）

1. 这个词是本项目**发明的或重新定义的**吗？（不是标准定义的搬运）
2. 一个熟练的高级工程师**搜索这个词也搜不到本项目中的含义**吗？
3. 不解释这个词，工程师**真的会误解代码意图**吗？

三问中任一回答"否" → **不收录**。不确定时默认不收录。

## 必须收录

- 项目自创的缩写词（如 TDH = Trusted Data Hub，项目自造的服务名）
- 项目内部组合概念（如「母 DID / 子 DID」「VP 网关」「同源双二进制」）
- 团队内部约定的简称（如 OC = 运营中心，common = 企业管理台）
- 代码中高频出现但名字不自解释的标识符（如 EnKey、VcSyncer、compatiblev2）
- 容易混淆的近义词对，且仅限本项目需要区分的（如 Issuer VC vs Holder VC）

## 禁止收录（严格执行）

- 行业公知术语（API、SDK、CI/CD、Docker、Kubernetes、HTTP、gRPC）
- 编程语言标准概念（goroutine、channel、interface、Promise）
- 通用数据库概念（SQL、索引、事务、ORM）
- 通用设计模式名称（MVC、单例、观察者）
- **有公开标准/规范定义的协议术语**（DID、DID Document、VC、VP、W3C、OAuth2、OIDC、JWT、JSON-LD）
- **通用基础设施概念**（KMS、HSM、SSO、DAL、DAO、MQ、CDN、LB）
- **名字自解释的外部服务/机构**（如 CFCA=中国金融认证中心、GLEIF=全球法人识别编码基金会）
- **标准角色名**（如 Issuer/Holder/Verifier 在 VC 生态中的含义）

## 采集步骤

### 1. 识别候选术语

扫描以下来源：
- 代码中的 package 名、核心 struct/class 名（尤其是缩写命名且搜索不到含义的）
- 配置文件中的非自解释 key
- 团队文档中反复出现但从未展开定义的词

### 2. 严格过滤（默认丢弃，只有明确通过才保留）

| 条件 | 结论 |
|------|------|
| 能在 Google/Wikipedia/W3C/RFC 中搜到且含义完全一致 | **丢弃** |
| 是某个公开标准定义的术语（哪怕项目用了这个标准）| **丢弃** |
| 是通用架构/基础设施概念 | **丢弃** |
| 名字已经自解释含义（如 AuthService = 认证服务）| **丢弃** |
| 确认是项目自创、组合、或重新定义的 | **保留** |

### 3. 写入格式

- 定义写的是「本项目中这个词具体指什么」，不是百科解释
- 如有别名/历史叫法，一并列出
- 如有易混淆的对照组，放入「易混术语对照」段

## 约束补充

- 不确定是否项目私有 → **不收录**（不标 TODO，直接丢弃）
- 禁止为了"看起来完整"而填充通用术语凑数
- 禁止收录后在定义里写通用解释（如「DID 是 W3C 制定的去中心化身份标识符标准」——这是百科搬运）
- 如果一个术语删掉后，工程师读代码不会产生误解 → 不需要收录
