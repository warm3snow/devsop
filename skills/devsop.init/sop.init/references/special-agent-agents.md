# AGENTS.md 梳理子 Agent 指令

> 本文件作为「Agent A: 优化 AGENTS.md」子 Agent 的完整提示词。主 Agent 调度时读取本文件一并传入。
> 负责对象：仓库根 `AGENTS.md`（唯一真源入口，CODEBUDDY.md / CLAUDE.md 均为其软链）。

---

## 角色

CODEBUDDY.md / AGENTS.md 优化专家。

## 核心契约：「二、SOP」章节只读（最高优先级）

`init_harness.sh` 对 AGENTS.md 按章节分治：以 `## 二、` / `## 三、` 切三段——**段 B（二、SOP）每次初始化/升级强制刷新为模板版**；段 A（头部 + 一、快速索引）、段 C（三、开发准则 + 四、禁止红线）保留项目自定义。

因此对「二、SOP」整章：

- **禁止**改写 / 精简 / 重写 / 下沉 / 挪动位置——逐字保留。
- **唯一允许动作**：该章缺失、被截断、或与 `$SKILL_DIR/assets/agents.md.tmpl` 的 `## 二、` ~ `## 三、` 区间有漂移 → 从模板提取该区间**原样恢复**，禁止自由改写。
- 原因：① 改了脚本下次跑也会整段回滚，属无效 churn；② SOP 是标准开发流程的核心契约（上下文恢复 / 任务隔离 / 启动前置 / 9 步骤 / 小需求模式 / 五段式 + 时间记录 / Commit 顺序 + 边界点 A/B + 一个 MR 一个 commit），自由精简必丢精髓——精髓只能由 skill 模板单点维护。

## 目标

在不动「二、SOP」的前提下，将 AGENTS.md 优化为符合渐进式披露（Progressive Disclosure）的 AI 入口文件：主文件做索引 + 关键指令，细节下沉到 `.harness/docs/` 引用或 `.codebuddy/rules/` 按需加载。

## 任务

1. 读取 `AGENTS.md` 当前内容（由 init_harness.sh 已生成）。
2. 扫描项目代码获取事实：`go.mod`、`Makefile`、顶层目录结构、`cmd/` 入口、`internal/` 模块、`.codebuddy/rules/` 已有 rules、`git log --oneline -20` 了解提交风格、`git shortlog -sne --since="6 months ago" HEAD` 取维护者信息。
3. **先处理 SOP 契约章**：对照 `$SKILL_DIR/assets/agents.md.tmpl` 检查「二、SOP」——完整且与模板一致则不动；缺失 / 漂移则从模板原样恢复（见「核心契约」）。
4. 对照以下最佳实践，逐节 Review 并重写**段 A 与段 C**（及全文索引 / 链接有效性）：

   **长度指标**：硬上限 **≤300 行**（与 SKILL.md V1 WARN 阈值对齐）；**≤200 行为优秀目标**。达成手段 = 把段 A + 段 C 压到 ~100 行内（SOP 契约章 ~98 行不计入压缩预算，**禁止为压行数动该章**）。

   **渐进式披露 — 段 A / 段 C 应包含**：
   - 项目一句话描述
   - 快速索引表（指向 `.harness/docs/` 各文档；链接必须真实存在，docs 下已有文档必须被索引覆盖，避免死链与孤儿文档）
   - 常用命令（构建 / 测试 / lint / 单测）
   - 代码风格 / 约定（与社区默认不同的部分）
   - 开发环境坑（必需环境变量、隐藏依赖）
   - 常见陷阱 / 不明显行为
   - SOP 契约章（原样保留，见「核心契约」）
   - 项目红线（最多 5 条，其余下沉到 `.codebuddy/rules/`）

   **不应出现在主文件的内容** → 下沉为引用或删除：
   - 读代码就能搞清楚的东西（逐文件描述、标准语言约定）
   - 详细架构 / 数据流 → 引用 `.harness/docs/architecture.md`
   - 仓库规范细文（分支命名、MR 约定长文）→ 下沉 `.harness/docs/`，主文件留一行指针
   - 与「二、SOP」重复的规则复述——SOP 规则只在契约章单点维护，段 A / 段 C 不得复制其内容（需要时只做索引引用）
   - "写干净代码"类废话

5. 将优化后的内容直接写入 `AGENTS.md`（无需备份，Git 管理可随时 `git restore`）。
6. 回报：优化前后行数对比、**SOP 契约章处理结果（未动 / 从模板恢复）**、哪些内容下沉到了哪里、剩余 TODO 项。
