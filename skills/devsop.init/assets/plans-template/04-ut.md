## Case Design Checklist

To ensure coverage, self-check each tested function against the following list:

### Input dimension
- [ ] Empty input / None / empty string / empty list / empty dict
- [ ] Single element / multiple elements
- [ ] Minimum / maximum / over limit
- [ ] Wrong type (str given where int expected)
- [ ] Invalid characters / injection-type (SQL, path traversal, scripts)
- [ ] Unicode / Emoji / over-length characters

### State dimension
- [ ] Resource does not exist
- [ ] Resource already exists / conflict
- [ ] Resource state mismatched with the operation (e.g. shutting down an already-terminated instance)
- [ ] Concurrent race (can be simulated with a mocked clock)

### Dependency dimension
- [ ] Dependency returns success
- [ ] Dependency returns a business error
- [ ] Dependency times out
- [ ] Dependency throws an exception

### Idempotency / retry
- [ ] Same request repeated, results consistent
- [ ] Retry after partial success, no side effects

## Prohibitions (red lines)

- ❌ **Modify business code to make tests pass**. When tests and code diverge, first judge which side is right; if the code is wrong, open a bug-fix task, **do not** quietly change it within this task.
- ❌ **Call real external services**. Mock everything.
- ❌ **Dependency on execution order between cases**. Results must be identical regardless of execution order.
- ❌ **Hardcode environment information**. Use fixtures / config injection.
- ❌ **Insert new mocks / steps in the middle of a file**. Only append to the end of the file.

---

## Anti-examples

❌ **Anti-example 1: only test the happy path**
> Tested `login(user="alice", pwd="123456") == True`, but not wrong passwords, lockout, empty user, etc.

❌ **Anti-example 2: assertions too weak**
> `assert result is not None` — cannot catch most bugs.

✅ **Rewritten**
> `assert result.code == 0 and result.user_id == expected_id and result.session_token.startswith("sess_")`

❌ **Anti-example 3: mock return value inconsistent with reality**
> Mock DB query returns `{}`, but the real DB returns `None`.

✅ **Principle**
> Mocks should be based on real behavior; you may capture a real return once as a fixture.
